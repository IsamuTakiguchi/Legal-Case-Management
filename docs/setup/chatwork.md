# Chatwork の設定

## 1. API トークン

1. Chatwork にログイン → 右上のアカウント名 → サービス連携 → **API Token**
2. パスワードを入力して表示されるトークンを `.env` の `CHATWORK_API_TOKEN` に設定

> 組織契約の場合、管理者が API の利用を許可している必要があります。

## 2. Webhook（推奨）

Webhook を設定すると受信が即時になります。設定しなくても 5 分ごとのポーリングで取り込みます。

1. サービス連携 → **Webhook** → 新規作成
2. Webhook URL: `https://<公開URL>/webhooks/chatwork`
3. イベント: **アカウントイベント**（自分宛メンション／全メッセージ）を選択。ルームイベントを使う場合は依頼者ごとのルームを追加
4. 作成後に表示される **トークン** を `.env` の `CHATWORK_WEBHOOK_TOKEN` に設定（署名検証に使います）

> Chatwork の Webhook は失敗時に再送されず、連続で失敗すると自動停止します。アプリは常にポーリングも併用するため、取りこぼしはポーリングで補われます。

## 3. 通知先

返信待ちの期限超過や朝のダイジェストは **マイチャット** に投稿します。特定のルームに送りたい場合は `CHATWORK_NOTIFY_ROOM_ID` にルーム ID（URL の `#!rid` の後ろの数字）を設定してください。

## 4. 依頼者の紐付け

依頼者ごとのルーム（グループチャットまたはダイレクト）の **ルーム ID** を依頼者に登録すると、そのルームの受信が自動で紐付きます。未登録のルームからの受信は「未紐付けの連絡先」として届くので、そこから紐付けることもできます。

## 5. タスクの同期

- アプリで作成したタスクは「Chatwork にも作成」を選ぶとマイチャットのタスクとして登録されます
- **Chatwork で自分に振られたタスクは、10 分ごとに自動でアプリに取り込みます。** ボタンを押す必要はありません。待たずに取り込みたいときは、タスク画面の「Chatwork から今すぐ取込」を押してください
- 取り込むのは未完了のタスクだけです。すでに取り込んだものは重ねて増えません。期限が付いていれば「期日」として入ります
- Chatwork 側で完了するとアプリでも完了になり、アプリで完了にすると Chatwork 側も完了になります
- 事件の担当事務局に振ったタスク（自分のタスク一覧には出ないもの）は、ルームごとに状態を確かめるので、相手が終えていないのに完了になることはありません。状態を確かめられなかったときは、そのまま残します

## 6. リアクション（ワンタップ返信）

会話画面の受信メッセージに「😊 リアクション」があります。押すと「✅ 了解」「🙏 ありがとう」などのボタンが出て、選ぶとその場で送信されます。

**Chatwork のリアクション機能そのものは公開 API（v2）に無いため、アプリからメッセージにリアクションを付けることはできません。** 代わりに、そのメッセージへの**返信**として短い一言を送ります。相手の画面には、返信タグの付いた「(roger) 了解しました」のような短いメッセージとして届きます。

ボタンの中身は 設定 →「Chatwork のリアクション（ワンタップ返信）」で変えられます。1 行に 1 つ、`ラベル|送る本文` の形です。本文には Chatwork の絵文字コードが使えます。

```
了解|(roger) 了解しました
ありがとう|(bow) ありがとうございます
いいね|(y)
```

空にすると、Chatwork のリアクションと同じ顔ぶれ（了解・おじぎ・いいね・拍手・にっこり・びっくり）の 6 つに戻ります。

## 7. 制限

- ファイル送信は 5MB まで。超えるものは OneDrive の共有リンクとして送ります
- API は 5 分間に 300 リクエスト、投稿はルームごとに 10 秒間に 10 件までです
- メッセージへのリアクション（絵文字を付ける機能）は API に無いため、上記のとおり「短い返信」で代用しています

## 事務局からの伝言として使う場合

Chatwork の相手が依頼者ではなく事務所内の事務局メンバーである運用（伝言・連絡が中心）では、次の設定をします。

1. 設定 → 事務局メンバー に、伝言をくれる方を登録します。「Chatwork の参加ルームから候補を読み込む」で Chatwork のアカウントを選ぶと、その人からのメッセージを「事務局」として扱い、依頼者の未紐付け警告を出しません。
2. 事件ページの「担当事務局」で、その事件の担当者を選びます。事件から作る Chatwork タスク（受信箱の「タスク化」で「担当事務局の Chatwork タスクにも登録」を付けたものなど）は、この担当者に振られます。
3. 事件専用のグループチャットがある場合は、事件ページの「事件専用の Chatwork ルーム」で指定します。そのルームのメッセージはすべてその事件の記録に入ります。
4. 全体ルームの伝言は、本文に依頼者名（フルネーム・別名・2 文字以上の姓）があれば、その依頼者と進行中の事件に自動で紐付きます。判定できなかったものは会話画面の各メッセージの「紐付け」で指定します。

取込範囲を「自分宛だけ」にしている場合は、[To] で自分が指定された伝言、自分のメッセージへの返信（re）、全員宛（toall）、ダイレクトチャット、自分に振られたタスクのメッセージだけが受信箱に入ります。

判定は次のとおりです。

- **引用（[qt]）の中は見ません。** ほかの人あてのメッセージに、昔の [To:自分] を含むやり取りが引用されていても、自分宛とは扱いません
- **自分の発言**は、ダイレクトチャットならそのまま入ります。グループチャットでは、すでに取り込んだメッセージへの「返信」だけが入ります（関係のない発言は入りません）。アプリから送った分は取込範囲にかかわらず残ります
  - グループで Chatwork の「返信」を使わずに書いた自分の発言は入りません。やり取りを残したいときは Chatwork の返信ボタン（または本アプリの返信）を使ってください

### 取り込まれた理由を確かめる

「自分宛だけ」なのに範囲外が入っているように見えるときは、推測せず次の 2 か所で確かめてください。

- **会話画面**: Chatwork の受信 1 件ごとに「取込理由: [To] で自分が指定」のように、どの条件で入ったかが付いています。「記録なし（旧版で取り込み）」は、理由を記録する前の版で取り込んだものです
- **設定 → 接続状況 → Chatwork**: サーバーが実際に見ている取込範囲、最後の Webhook・ポーリングの時刻、直近 24 時間に取り込んだ受信の理由別の数が出ます。「自分宛だけ」なのに「理由の記録なし」が**増え続ける**なら、判定を通さずに入る経路が残っています

Chatwork 側の「自分宛メンション」(mention_to_me) イベントは、引用の中の [To:自分] でも発火することがあるため、本アプリはそれを信用せず、どのイベントでも同じ判定を通します。

### 動いている版を確かめる

設定 → 接続状況 の見出しの横に「動いている版: `abc1234`」と出ます。修正が反映されているか迷ったら、この 7 桁を GitHub の main の最新コミットと見比べてください。違っていれば、まだデプロイが終わっていないか失敗しています。

**取込範囲を変える前に取り込んだ分**には、この判定は当たっていません。設定 →「Chatwork の取込範囲」の下にある「取込済みの分を確認する」で、範囲外の受信が何件あるかを数え、そのまま外せます（外すのは相手からの受信だけで、自分が送った分は残ります）。「自分宛だけ」に切り替えたときは自動でも一度実行します。

## 7. 受信箱に届かないときは

Chatwork の受信は **Webhook（届いた瞬間）＋ 5 分ごとのポーリング（取りこぼしの補い）** の二本立てです。ポーリングは次のルームを見ます。

- 依頼者に紐付けたルーム
- すでに受信箱に取り込んだことのあるルーム
- 未読があるルーム
- **前回より動きのあったルーム**（Chatwork 側で先に読んで未読 0 になっていても拾います）

1 回のポーリングで見るルームは 60 件までで、超えた分は次の回にまわします（Chatwork の API 制限のため）。

それでも足りないときは、**設定 →「バックグラウンド処理」→「Chatwork 全ルームの取りこぼし拾い」の「今すぐ実行」**で、参加しているすべてのルームを見に行けます。この処理は毎晩 3:20 にも自動で回ります。

Webhook が止まっていないかも確認してください。Chatwork の Webhook は**失敗しても再送されず、連続して失敗すると自動で無効になります**（アカウント設定 → API → Webhook）。
